# DONUT Roadmap: Feature Improvements

**Date:** 2026-02-13
**Authors:** Yossi Bokor Bleile
**Status:** Proposal (for team review)

## Overview

This roadmap proposes improvements to DONUT organized into four phases,
ordered by impact-to-effort ratio. Each phase builds on the previous one.
The current codebase (849 lines of Python, 8 Flask routes, Xapian search,
554 BibTeX entries) is well-structured and each phase is designed to extend
it incrementally without major rewrites.

## Guiding Principles

- **Minimal dependencies:** Prefer solutions that work within Flask + Xapian
  over introducing heavy new infrastructure (no databases, no Redis, no JS
  frameworks).
- **Backwards compatible:** Every change must preserve existing URL patterns
  and search syntax.
- **Privacy-first:** No analytics, no tracking, no cookies. Any new features
  (e.g., saved searches) must work without user accounts.
- **Curation over automation:** DONUT's value is its curated focus. Features
  should enhance discovery within the curated set, not expand scope.

## Phase 1: Foundation & Quick Wins

**Effort:** Low (1-2 weeks each)
**Impact:** High
**Theme:** Make the existing data more accessible

### 1.1 REST API

Expose the existing data as JSON so researchers can build on DONUT
programmatically. Three endpoints:

| Endpoint | Maps to | Notes |
|----------|---------|-------|
| `GET /api/papers` | `get_documents()` | Filterable by tag, author, year |
| `GET /api/papers/<id>` | `get_document()` | Single paper detail |
| `GET /api/tags` | `get_tags()` | Tag hierarchy with counts |

No authentication needed (public data). Add `Accept: application/json`
content negotiation to existing routes as an alternative approach.

### 1.2 Result Sorting

Currently results from `/papers` and `/software` are returned in Xapian
docid order. Add sort controls:

- **Year (newest first)** — default for browse pages
- **Year (oldest first)**
- **Relevance** — default for search results (current behavior)

Requires storing `year` as a Xapian value slot for efficient sorting.

### 1.3 Pagination

The current `get_mset(0, n_documents)` loads all results. At 554 papers
this is fine, but it won't scale and the `/papers` page is already slow.
Add offset/limit pagination (25 results per page) using Xapian's native
`get_mset(offset, page_size)`.

### 1.4 RSS/Atom Feed

Publish newly added papers as an RSS feed at `/feed`. Researchers can
subscribe in any feed reader. Requires sorting papers by date added
(use git commit date of the `.bib` file, or add a `date-added` field
to Zotero).

### 1.5 Bulk BibTeX Export

Add an "Export all results" button that bundles all papers in the current
search result into a single `.bib` file download. Useful for survey
authors building bibliographies.

## Phase 2: Enhanced Search & Filtering

**Effort:** Medium (2-3 weeks each)
**Impact:** High
**Theme:** Make search more accessible to non-power-users

### 2.1 Faceted Search Sidebar

After a search, show a sidebar with refinement options:

- **Tags** (grouped by applications/tools/data) with counts
- **Year range** slider or buckets (2015-2019, 2020-2024, 2025+)
- **Entry type** (paper vs software)
- **Flavour** (innovate vs confirm)

Each filter appends to the current query. Clicking "Persistent Homology (42)"
in the tools facet adds `AND tag:"persistent homology"` to the query.

Implementation: Compute facets server-side by scanning the result set.
At 554 documents, this is fast enough without precomputation.

### 2.2 Search Autocomplete

As the user types, suggest:

- Known tags (from the tag index)
- Author names (from the `A` prefix terms)
- Search syntax hints (`author:`, `tag:`, `title:`)

Implementation: A lightweight `/api/suggest?q=...` endpoint that queries
Xapian's term iterator. No JavaScript framework needed --- a simple
`<datalist>` element or small vanilla JS fetch.

### 2.3 Year Range Filtering

Add `year:2020..2024` syntax to the query parser, mapping to Xapian
value range queries. Also expose as a UI control on the search page.

## Phase 3: Discovery & Exploration

**Effort:** Medium-High (3-4 weeks each)
**Impact:** Medium-High
**Theme:** Help researchers discover connections they didn't know to search for

### 3.1 Related Papers

On each paper's display, show 3-5 related papers. Similarity computed by:

1. **Tag overlap:** Papers sharing the most tags (Jaccard similarity)
2. **Author overlap:** Papers by the same authors

Precompute a similarity matrix at index time (554x554 = ~300K pairs,
trivially small). Store top-5 neighbors per paper as a Xapian document value.

### 3.2 Tag Co-occurrence Visualization

An interactive page showing which tags appear together. Two views:

- **Matrix heatmap:** Tags on both axes, cell color = co-occurrence count
- **Network graph:** Tags as nodes, edges weighted by co-occurrence

This directly surfaces research clusters (e.g., "persistent homology" +
"point cloud" + "materials science" form a cluster). Use a lightweight
JS library (D3.js or vis.js) for the interactive graph.

Data: Precompute a co-occurrence matrix at index time. Expose via
`/api/tag-cooccurrence`.

### 3.3 Timeline View

A page at `/timeline` showing papers plotted by year, colored by
application domain. Reveals trends like "TDA in neuroscience accelerated
after 2018."

Implementation: Server renders year-grouped data. A small D3.js or
Chart.js visualization. Can also work as a static SVG for zero-JS
fallback.

### 3.4 Paper Statistics Dashboard

A page at `/stats` showing:

- Papers per year (bar chart)
- Top 10 tags by frequency
- Top 10 authors by paper count
- Growth over time
- Application domain distribution

All computable from existing indexed data.

## Phase 4: Software Catalog & Cross-Referencing

**Effort:** Medium
**Impact:** Medium
**Theme:** Make DONUT the go-to resource for "which TDA tool for my problem?"

### 4.1 Expand Software Catalog

Currently 2 entries. Actively catalog major TDA tools:

- GUDHI, Ripser, giotto-tda, scikit-tda, DIPHA, Dionysus, javaPlex,
  HomCloud, TopologyToolKit, BATS, etc.

For each tool, capture:
- Language/platform
- Input data types supported
- TDA methods implemented
- Maintenance status (active/archived)
- Documentation quality

This is primarily a **curation effort**, not a code change. The existing
BibTeX `software` entry type handles it. May need 2-3 new keyword
categories for language, platform, and status.

### 4.2 Software-Paper Cross-Referencing

Tag papers with the software they use (new keyword category, e.g.,
`S - GUDHI`). This enables queries like "show me all papers that use
Ripser" and helps researchers choosing between tools see real-world
usage examples.

### 4.3 Tool Comparison Page

A dedicated page at `/software/compare` showing a feature matrix:
tools vs. capabilities. Which tools support persistent homology? Which
handle 3D point clouds? Derived from the software catalog metadata.

## What This Roadmap Does Not Include

Deliberately excluded to keep scope focused:

- **User accounts / authentication** --- against DONUT's privacy principles
- **Full-text PDF search** --- copyright concerns
- **Mobile app** --- the web interface with responsive CSS is sufficient
- **Citation graph from external sources** --- requires Semantic Scholar /
  OpenAlex integration with rate limits and maintenance burden. Revisit
  once the API (1.1) is established.
